# Live Trading 2.0 · етап B: ізольований прототип потоку цін Binance

**Лише читання публічних WebSocket Binance.** Не торгує, не читає й не пише `data/` та гілку `data`, не імпортує код торгового рушія,
не пов'язаний із сайтом, GitHub Actions чи Pages. Логи пишуться тільки в `prototypes/live2/logs/` (у `.gitignore`).

## Що вимірює
- котирування `miniTicker` і `kline` (за замовчуванням 15m та 1h; `--book` додає `bookTicker`) для 10 паперових монет: BTC, ETH, BNB, SOL, XRP, DOGE, ADA, LINK, AVAX, SUI;
- частоту повідомлень, інтервал між ними, затримку `p50 / p90 / p99` (час отримання мінус час події біржі `E`);
- затримку закритої свічки відносно її кінця (`T`), пропуски закритих свічок, порушення порядку;
- перепідключення: причина, час простою, частка доступності;
- «тишу» (stale): якщо немає жодного повідомлення довше `--stale` секунд, з'єднання вважається мертвим і замінюється.

### Про точність затримки
Абсолютна затримка = локальний час отримання + зсув годинника − час події біржі. Зсув береться з `GET /api/v3/time` (зразок із мінімальним RTT),
тому похибка ≈ RTT/2 (`latency_error_bound_ms` у підсумку). Поруч показується «сирий» вимір без поправки (`raw_miniTicker_minus_event_ms`):
він точний лише коли годинник ПК синхронізований із NTP. Розкид (p99 − p50) і частота не залежать від зсуву.

## Запуск
```
cd prototypes/live2
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt     (Linux: .venv/bin/python)
.venv\Scripts\python -m live2.run --duration 600
.venv\Scripts\python -m live2.run --duration 900 --chaos-at 120,300   # грубі обриви зв'язку для перевірки відновлення
.venv\Scripts\python -m live2.run --duration 0                        # працювати до Ctrl+C / SIGTERM
```
Підсумок: `logs/run-<час>-summary.json`, журнал подій і щохвилинних зрізів: `logs/run-<час>.jsonl`.

## Тести
```
.venv\Scripts\python -m unittest discover -s tests -v
```
Тести працюють на локальному фейковому WebSocket-сервері (без мережі): отримання, чисте завершення, перепідключення після закриття сервером,
виявлення тиші, грубий обрив, резервний хост, ріст паузи з обмеженням, планова ротація, некоректний JSON, пропуски свічок, порядок повідомлень,
книга цін і актуальність, а також перевірки ізоляції (немає імпортів рушія, звернень до `data/`, торгових ендпойнтів і ключів).

## Склад
| Файл | Призначення |
|---|---|
| `live2/feed.py` | з'єднання: перепідключення, джитер, ротація хостів, stale-контроль, чисте завершення |
| `live2/recorder.py` | облік затримок, частоти, інтервалів, пропусків, простоїв; щохвилинні зрізи |
| `live2/pricebook.py` | останні ціни в пам'яті з перевіркою віку |
| `live2/clock.py` | зсув годинника відносно Binance |
| `live2/stats.py` | відсотки (найближчий ранг), вибірка обмеженого розміру |
| `live2/run.py` | командний рядок |
| `tests/test_live2.py` | тести |

## Запуск на VPS
Потрібно: Python ≥ 3.10, пакет `websockets`, вихідні з'єднання на `stream.binance.com:9443` (або `:443`) і `data-api.binance.vision:443`;
регіон сервера, з якого Binance не блокує доступ (ЄС); синхронізований годинник (`chrony` або `systemd-timesyncd`) для точних абсолютних затримок.
Для постійної роботи — `systemd`-сервіс із `Restart=always`, користувач без привілеїв, запис лише в `logs/`. Секретів прототип не використовує.
